# Wine 11.20 的文档输入桥核验

[返回输入桥说明](docs-ime.md) · [Wine 11.19 记录](docs-ime-wine19.md)

2026-10-26，实际安装的 Arch `wine-11.20-1` 已更新系统与前缀 DLL，
旧文档输入桥的整组哈希仅允许 11.18/11.19，因此在 `imm32.dll`
检查处停止。此处是过期兼容清单停用，未证实为 11.20 新增输入法回归。

## 本次改动及验证

新增 `wine-11.20-1` 配置，保留 `wine-11.18-1` 和 `wine-11.19-1`。
仍要求系统与前缀的全部 7 项 Wine 组件属于同一配置；
企业微信、CEF 宿主及文档宿主的 3 项固定哈希与窗口范围限制不变。

从 Wine 官方镜像的 `wine-11.19`、`wine-11.20` 标签取得源码，
比较下列 8 个文件，全部逐字节相同：

| 源文件 | 输入桥依赖 |
| --- | --- |
| `include/immdev.h` | 100 字节组合文字结构 |
| `include/ntuser.h` | 16 字节 i686 参数布局、两个私有调用编号 |
| `dlls/win32u/imm.c` | 读取已有更新的长度查询与取出语义 |
| `dlls/win32u/message.c` | 私有消息转交 |
| `dlls/wow64win/user.c` | 32 位指针与参数转换 |
| `dlls/winex11.drv/xim.c` | XIM 更新投递与候选位置 |
| `dlls/imm32/imm.c` | 目标端公共 IMM 提交 |
| `dlls/imm32/ime.c` | 输入法布局判断 |

源码地址：
<https://github.com/wine-mirror/wine/tree/wine-11.20>。
各文件 SHA-256 保存在 `modules/docs-ime/abi-evidence.json`，
安装组件哈希保存在同目录的 `module.json`。

实机 `start.py --verify-only` 接受当前完整 11.20 系统与企业微信前缀；
输入桥 DLL 和守护程序通过 `-Wall -Wextra -Werror` 编译。
输入桥、三版本混用边界和文档 DLL 策略的 27 项测试通过，
另有 3 项源码核验边界测试通过。
本记录不声称已完成实际共享文档候选、上屏及光标移动验证。

## 后续升级如何减少重复核验

Wine 公共接口兼容不能保证这里使用的私有调用编号、WOW64 布局和队列
协议兼容。仅检查 DLL 导出名、忽略版本号或删去哈希保护，会让错误调用
进入企业微信进程，因此本模块保留整组二进制门禁。

新增只读源码核验命令，用于快速确定下一次升级的接口审查范围：

```sh
python3 modules/docs-ime/audit-source.py --source /path/to/wine-source
```

传入与待核验安装包版本对应的上游源码目录。文件全部相同返回 0；
文件缺失、改变或指向目录外返回失败，需要人工查看对应差异。
该命令不下载或启动程序、不编辑兼容清单、不自动授权未知安装包。
源码相同后仍要核对实际安装包来源、系统与前缀一致性，再完成构建和
界面验证。与 Wine 无关的企业微信版本更新仍需单独检查宿主程序。

## 白屏补丁检查

`docs` 修补企业微信自带 `libcef.dll` 的 V8 页面保护判断，
并不替换 Wine DLL。当前原件 SHA-256 为 `007385e8…`，
私有补丁为 `8f896cc2…`，均与该模块固定的完整哈希一致，
此次 Wine 更新无需重做白屏补丁或放松企业微信组件校验。
完整哈希、修改字节与跳转验证见 `modules/docs/patch-libcef.py`。
