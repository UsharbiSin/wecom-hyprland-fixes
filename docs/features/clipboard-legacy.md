# 旧全局剪贴板服务的停用与迁移

[返回总览](../../README.md) · [当前图片修复](clipboard.md)

## 旧方案的行为

旧的 `clipboard-image-compat.py` 配合 `wecom-clipboard.service`，
监听 Wayland 剪贴板，保存便携 MIME 快照，用 Pillow 增补 PNG/BMP，
必要时把图片存为临时文件并增加 `text/uri-list`，再交给 GTK 发布器。
部分版本还包含 WPS 前台窗口判断和应用私有格式跳过规则。

该方案能为普通图片提供更多格式，但重新发布意味着可能改变剪贴板所有者。
WPS 和 Wine OLE 剪贴板的数据可能依赖原进程，不能只保存 MIME 名称，
就假定能够重新创建原来的富格式对象。
文件 URI 也可能让接收端把截图当附件，不能等同于聊天框内直接图片粘贴。

## 为什么应停用旧服务

全局剪贴板改写可能破坏 WPS 单元格复制、公式和格式刷所依赖的原始数据。
即使脚本日志显示新增图片格式，也只能说明格式转换完成，
不能证明企业微信能直接粘贴，或 WPS 的原始复制语义被保留。

当前方案改为恢复企业微信输入回调，并仅给其自有图片追加缺失 PNG。
两个方案不应同时运行。安装当前模块前，应确认旧服务已经停止，
并移除旧启动器中的自动启动命令。
当前模块不会安装旧监听服务，回滚时也不会重新启用它。

## 从旧部署迁移

先查看服务状态；这只读取状态，不读取剪贴板内容：

```bash
systemctl --user show wecom-clipboard.service \
    -p ActiveState -p SubState -p UnitFileState
```

`inactive/dead` 表示当前未运行。
`static` 只表示单元没有可启用的安装段，其他程序仍可能手动启动它；
不能仅凭 `static` 判断旧服务已经停用。

如果旧服务存在且仍在运行，停止它：

```bash
systemctl --user stop wecom-clipboard.service
```

查看自己维护的旧启动器，移除显式启动该服务的命令。
不要用早期启动器备份整体覆盖当前脚本，避免恢复旧服务自动启动，
或者丢失后来加入的文档、摄像头、窗口等修复。

然后按[当前模块说明](clipboard.md#构建与安装)构建和安装。
验收应同时包含双向图片、文字和 WPS 富格式行为。
不需要删除个人原有脚本或历史备份，便于对照和排错。

## 迁移后仍有问题

`CONVERTED` 或 `FILE_URI_CREATED` 表示旧服务完成了转换或文件缓存，
`active` 只表示服务进程正在运行。
这些状态不能说明接收应用已经成功显示图片，也不能确认 WPS 富格式正常。

完成迁移后，按[当前模块的验收步骤](clipboard.md#安装后的人工验收步骤)
分别检查双向图片、文本粘贴和 WPS 表格行为。
