# CopyQ 企业微信图片历史预览

[返回首页](../../README.md)

## 解决的问题

企业微信复制的图片可以粘贴，但 CopyQ 历史只保存了文字/HTML，
因此历史列表缺少缩略图，从历史选回时也可能缺少可粘贴的图片格式。
`copyq` 模块为后续符合条件的历史条目补充 PNG。
既有的无预览记录不会被改写，需要重新复制。

这是 CopyQ 默认会话的桌面配置，同一用户的企业微信前缀共享一条规则。
它与修复 Wine 图片输入的 `clipboard` 模块分别安装、检查和移除。
不需要编译、指定 Wine 前缀、退出企业微信或更换启动器。

## 安装与移除

先安装并正常启动 CopyQ，确认已启用剪贴板历史保存和图片显示。
本次原生接口验证使用 CopyQ `16.0.0`；其他版本需重新检查。
规则需要实时剪贴板已能提供 `image/png`，
只有 Windows 私有图片格式时不会自动生成 PNG。
图片输出可结合[图片剪贴板模块](clipboard.md)使用。

```sh
./wecom-fix install copyq --dry-run
./wecom-fix install copyq
./wecom-fix doctor
```

安装只添加一条自动命令，不访问历史内容，也不写入当前剪贴板。
重复安装相同规则不会增加副本。规则位于自动命令列表前端，
原有命令的内容、匹配正则与相互顺序保留。
需要升级规则时先移除，再从新版本仓库安装：

```sh
./wecom-fix remove copyq
./wecom-fix install copyq
```

移除只删除记录中未被修改的专用命令，保留安装后对其他命令的编辑。
已保存的历史图片、其他历史数据与安装前备份都保留。
使用早期手动部署脚本安装的同名/同标识规则不会被接管或覆盖，
请先按该部署方式移除旧规则。不要直接导入整份旧备份覆盖当前命令。

## 补全条件与边界

- 只处理系统剪贴板事件，跳过鼠标选区和已有 PNG 的历史条目。
- 要求企业微信的 `WeWork Message` 格式和单个本地文件 URI。
- 对带 CopyQ `secret` 或 `hidden` 标记的内容直接跳过。
- 历史事件 HTML 必须与当前剪贴板一致；读取 PNG 前后复核来源和 URI。
- 最多等待 900 毫秒；剪贴板切换、读取失败或格式不符合时保持原事件。
- PNG 最多 64 MiB，宽高不超过 4096；超出限制的图片不补预览。

规则仅调用 `setData("image/png", ...)` 补充当前历史事件。
不重新持有实时剪贴板，不覆盖 `Ole Private Data` 或企业微信私有格式，
不读取 URI 指向的文件，不转换其他程序的剪贴板。
原 PNG 由 CopyQ 读取并解码/重新编码，规则还检查结构标识与尺寸边界。
若其他自动命令主动删除或改写历史数据，最终效果仍取决于这些命令。

## 配置保护

安装、移除使用 CopyQ 原生的 `commands()` / `setCommands()` 接口。
已有命令对象及正则始终保留在 CopyQ 进程内，
只有新规则的普通字段通过 JSON 传入，避免正则被转换成 `[object Object]`。
检查使用原生导出文本，包括单条 `[Command]` 和多条 `[Commands]` 格式。

状态位于 XDG 数据目录的 `wecom-fixes/copyq/`，
默认对应 `~/.local/share/wecom-fixes/copyq/`。
目录仅当前用户可访问；原生命令备份、规则源码副本和安装记录均为私有文件。
写入前比较完整命令导出，配置已经变化时停止。
写入后再次核对自有规则和全部无关命令，失败时保留恢复记录。
`doctor` 检查已安装源码副本、原生规则及安装记录是否一致。
CopyQ 未运行时，已安装模块的检查会报错；不会启动或重置 CopyQ。
