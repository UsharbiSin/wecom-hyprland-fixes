# 回滚与迁移

[返回首页](../../README.md) · [使用说明目录](README.md)

## 常规移除

先正常退出专用前缀的企业微信及其子进程，再运行：

```sh
./wecom-fix remove clipboard --prefix "$WECOM_PREFIX"
```

每个模块分别移除，不需要重装其他模块。
工具恢复原注册表值，删除安装副本，并按记录恢复新增会议兼容库。
文件视图绑定只对旧进程生效；下次从统一入口启动时才体现移除结果。

## 为什么拒绝回滚

如果当前注册表值已被后续修改，或兼容库与备份哈希改变，工具拒绝覆盖。
这意味着存在需要人工判断的配置冲突，不是删除整个状态目录的理由。

1. 先保留当前状态目录和原前缀副本。
2. 对比模块 `installed.json` 中的原值、安装值及当前值。
3. 明确哪个变更需要保留，再手动恢复冲突项。
4. 重新运行 `remove`，确认剩余项目恢复。

安装中断会留下未完成标记，该模块不能启动；先回滚再重新安装。

## 旧部署迁移

旧方案可能包含直接替换 Explorer、全局剪贴板服务、
主配置内的窗口规则以及旧版 qcap。不要把早期启动器备份整体写回。
应逐项对照功能文档，选择迁移，保留现有正常工作的入口作为对照。

- 旧剪贴板服务停止后，再启用新的专用剪贴板模块。
- Hyprland 片段只加入一次，移除冲突的旧企业微信规则。
- Wine 更新后失效的旧相机补丁先保持停用，不能强行载入。
- Office/MIME 的手动关联、微软安装器均遵循各自备份或卸载步骤。
- 不删除旧前缀，不把复制前缀后的新聊天数据合并回旧副本。
