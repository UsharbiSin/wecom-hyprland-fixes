# 系统 Wine 升级后的启动接续

此前的本地 wineserver 修复只接受 Wine 11.21。系统升级到 11.22 后，
旧会话仍可运行，但结束再启动时会被服务文件校验拒绝。
这类校验需要配套恢复路径，不能把拒绝启动当作升级兼容。

`tools/wine_runtime.py` 为已有专用启动器提供完整运行环境选择：

- 系统组件匹配已验证配置时，选择该版本的完整 Wine 环境。
- 系统版本尚未验证时，继续使用默认的完整已验证环境，并通知用户。
- 已有会话时按实际运行服务的哈希选择同版，避免升级中途混用。
- 运行环境损坏、会话身份不明时保留拒绝检查，并显示可见错误。

每套配置来自签名校验通过的发行版完整 Wine 包，保留对应服务修复。
映射仅作用于企业微信启动进程及子进程；不降级或覆盖系统 Wine。
映射包含程序、运行库、数据、头文件；所有文件及链接逐项核验，
不允许未登记文件、缺失目录或越界链接混入已验证环境。

当前本地配置支持 Arch Wine 11.21-1 和 11.22-1，默认 11.22-1。
旧版本的文档输入、图片输入配置继续保留。
11.22 使用与它配套重新构建的既有上游服务修复，不能复用旧二进制。
安装时必须替换旧 `WECOM WINESERVER JOB FIX` 包装块，不能叠加执行。
新的入口使用 `WECOM_WINE_RUNTIME_VIEW` 防止递归，并在每层核验视图。

## 验证范围

- 11.22 原服务的控制组通过，Job 关闭回归仍独立触发崩溃。
- 11.22 修复版 x64/x86 各七项测试通过，系统结束命令正常工作。
- 图片输入保留旧配置，11.19–11.22 各自重建及机器码验证通过。
- 文档输入桥增加完整 11.22 配置，源码 ABI 审查与夹具校验通过。
- 摄像头通过原自动构建流程生成 11.22 缓存并通过对照回归。
- 完整入口在隔离前缀中完成 11.21→11.22→11.21→11.22，
  以及未知系统指纹回退；各轮实际服务与十个前缀组件均配套。

专用前缀维护使用 `wineboot --init --update`，在更新阶段跳过
普通 Run/Startup 自启动项。原设置保持不变，企业微信在所有
兼容视图准备好后才由原入口启动，避免提前运行导致等待超时。

未来未知 Wine 版本不会直接套用旧的单个服务或补丁。
回退表示继续使用上一套完整已验证环境，不代表未知版本已经通过适配。
底层系统依赖、命令链接布局或企业微信自身变化仍可能需要单独维护；
组件校验不能替代真实共享文档、会议和图片粘贴的界面验收。

此工具是现有入口的附加部署层，尚未接入 `wecom-fix install`。
`installed.json` 由部署时的已验证包、产物和专用路径生成，
不应通过修改版本号或哈希跳过来源核验。
